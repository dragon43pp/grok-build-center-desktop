Everything Agent Session Center does, and how

What it is

Agent Session Center is a desktop application that gathers the sessions of several AI coding agents into one window. Each agent writes its history in its own format, in its own directory; ASC reads those event streams and projects them into a single, consistent list you can browse, search and resume from.

It does not run the agents, replace their terminal, or sit between you and the model. It observes the files they already write, and it opens the original terminal when you resume a session.

The eight agents

Eight agents are supported. They are not equally observable, and the app says so rather than pretending otherwise.

Claude Code
Full session history, tool lifecycle, permission prompts and token usage.
Codex CLI
Session history and tool events, with token totals per turn.
OpenCode
The deepest reader of the eight: history, tool lifecycle and message summaries.
Grok Build
History and tool events; status falls back to low confidence when its observer goes quiet.
Kimi Code
History and tool events, with a thinking phase where the model reports one.
Pi
History and tool events; reports tokens and context rather than a single number.
Antigravity
Session history only — it has no live event path, so it never shows a live status.
WorkBuddy
Session history only, like Antigravity; it appears in the list but reports no live state.

These levels are not marketing tiers. Each one is declared in the adapters' source, and the app marks low confidence instead of guessing when an observer cannot be trusted.

Install

The builds are unsigned. Download the file for your platform, verify its SHA-256 against the published value, and run it. There is no installer service and no background updater that phones home.

  • Windows: run the Setup .exe. It installs per user and needs no administrator rights.
  • macOS: open the .dmg and drag the app to Applications. Because it is unsigned, the first launch needs a right-click, Open.
  • Linux: install the .deb, or make the AppImage executable and run it. Both find the agents already on your machine.

First run

On launch, the app scans the standard directories for each agent and lists whatever it finds. The first scan takes a few seconds; after that it watches those directories and updates as sessions start, progress and finish.

Nothing is uploaded. The scan reads local files and keeps its index on your machine.

The five screens

The application is five views over the same data, reachable from the left rail.

Session history

Every session, from every agent, in one column — newest first, with status, workspace and agent.

AI search

Describe what you were working on in plain language and get the session back.

Resume

One click opens the original agent in its own terminal, in the right directory, with the conversation continued.

Usage

Tokens and cost per agent per day, so a long session is not a surprise.

Feishu

When an agent blocks on a permission prompt, the request is pushed to your phone so you can approve it away from the desk.

Search

Search has two modes. The plain one matches text in the sessions already indexed. The AI one embeds your question and ranks sessions by meaning, which is how you find a session when you remember the problem but not the words.

Both run against the local index. If you have configured a model provider, the AI mode uses it for the embedding step only.

Feishu approvals

Feishu is optional and off until you connect it. When it is on and an agent reaches a permission prompt, ASC sends you a card with the command and two buttons.

Approving the card answers the prompt in the session; the agent continues in its terminal. Declining sends the refusal instead. Either way the session itself never leaves your machine — only the question and your answer travel.

If Feishu is not connected, everything still works; the prompts simply wait in the terminal as they always did.

Privacy and data

What does the app read?

The session files and event streams the agents already write, in their standard directories. It does not read your terminal screen and does not attach to the running process.

What leaves my computer?

By default, nothing. If you enable Feishu, only the permission question and your answer are sent to the Feishu service. If you enable AI search with a hosted provider, your query text is sent to that provider.

Where is the index stored?

In the application's own data directory, as a local database. Deleting that directory resets the app to a fresh scan.

Is there telemetry?

No. The app does not send usage statistics or crash reports anywhere.

Can I point it at a custom directory?

Yes. Each agent has a configurable root, so a non-standard install location can be added without moving files.

Troubleshooting

The app found no sessions.

Check that the agents have been run at least once so their history directories exist, then set the root manually for the ones installed in a non-standard place.

A session never shows a live status.

Some agents, such as Antigravity and WorkBuddy, have no live event path. Those sessions appear in history only, and the app says so.

The macOS app will not open.

The build is unsigned, so Gatekeeper blocks a plain double-click. Right-click the app and choose Open once; afterwards it launches normally.

Feishu cards are not arriving.

Confirm the connection is enabled in settings and that the bot is allowed to message you. Cards are only sent while a prompt is genuinely waiting for an answer.

If this page and the application disagree, the application is right — the page is written from the same source, but the build is the truth.
